# Playwright CI — estado e limites

Em verificação pública do GitHub Actions, os runs anteriores de `Playwright Tests` paravam em `actions/setup-node@v4`: o workflow solicitava cache `npm` sem `package-lock.json`; `npm ci || npm install` também não é instalação reproduzível com `bun.lock`. O workflow agora fixa Bun 1.4.2, usa `bun install --frozen-lockfile` e `bunx playwright install --with-deps chromium`. A etapa de pré-voo exige URL/chave pública do Supabase de **homologação** e duas identidades A/B por Secret; falta de configuração reprova explicitamente, não é sucesso nem substitui E2E. Não versionar credenciais nem usar produção.

**Ainda não está homologado:** `e2e/tests/navigation.test.ts` verifica principalmente navegação e redirecionamento e pode precisar de fixtures autenticadas para rotas internas. `tests/e2e/{sales,purchase,production}-golden-path.spec.ts` permanecem `test.fixme`. Um run remoto verde do workflow, quando existir, não prova O2C/P2P/PCP, RLS de banco, dados fiscais nem pagamentos. Implementar fixtures isoladas, login real, asserções de persistência e consultas A/B antes de desmarcar golden paths. O browser Chromium e o servidor são providos pelo runner; não houve ensaio completo do Playwright neste sandbox.
